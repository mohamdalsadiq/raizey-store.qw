## ما تنفذه هذه المرحلة

البوت يستقبل `/start` و`/test` وزر «فحص الربط بالمتجر» في الخاص من
مالك واحد محدد بالمعرف الرقمي. يفحص الوصول إلى جدول الطلبات باستخدام
طلب `HEAD` لا يحمل بيانات عملاء، ثم يرسل نتيجة الاتصال للمالك.

هذه ليست لوحة إدارة مكتملة. لا توجد تنبيهات طلبات تلقائية أو تحديثات حالات
أو إرسال إيصالات أو تعاملات مالية في هذه المرحلة. نجاح الاختبارات المحلية
لا يعني نجاح الربط الفعلي؛ يجب تنفيذ `/test` من البوت بعد إعداد الأسرار والنشر.

## الإعداد الآمن

### الإعداد عبر Vault (المستخدم في مشروع المتجر)

المهاجرة `telegram_admin_vault_configuration` تضيف قارئ إعدادات خاصاً في
`private`، وواجهة RPC بصلاحيات `service_role` فقط. المالك المشاهد في محادثة
Saved Messages وسر webhook العشوائي يحفظان كإعدادات مشفرة في Vault.

المفتاح المتبقي يضاف من حساب مالك المشروع في Supabase Vault باسم
`meem_telegram_bot_token`. لا يوضع المفتاح في Git أو في محادثات الدعم.
الإعدادات الأخرى هي `meem_telegram_webhook_secret` و`meem_telegram_owner_id`.
يمكن تغيير المفتاح في Vault؛ يعيد الخادم قراءة الإعدادات كل 30 ثانية.

الوصول إلى `public.telegram_admin_configuration()` ممنوع عن `anon` و
`authenticated`، حتى لو كان المستخدم مديراً في واجهة الموقع. الدالة العامة
`SECURITY INVOKER`؛ قارئ Vault المعزول داخل `private` هو وحده `SECURITY DEFINER`،
وببحث أسماء فارغ وفحص دور الخادم. لا يتم كشف Vault عبر REST مباشرة.

### بديل: أسرار Edge Functions

1. أنشئ بوت المتجر من حساب المالك عبر BotFather الرسمي.
2. احفظ القيم التالية في Supabase Dashboard → Edge Functions → Secrets:
   - `TELEGRAM_BOT_TOKEN`: مفتاح البوت، ولا يُنشر في الكود أو المحادثات أو روابط المتصفح.
   - `TELEGRAM_OWNER_ID`: رقم حساب الإداري في Telegram، وليس اسم المستخدم أو رقم الهاتف.
   - `TELEGRAM_WEBHOOK_SECRET`: قيمة عشوائية مستقلة بطول 32 حرفاً على الأقل،
     من الأحرف والأرقام و`_` و`-`.
3. انشر `telegram-admin` على مشروع `rglbfizqolrenwfsndyv`.
   الدالة تستخدم أسرار Supabase الخادمية المحقونة تلقائياً. تفضل المفتاح
   المسمى `telegram` ثم `default` من `SUPABASE_SECRET_KEYS`، مع دعم المفتاح القديم.
   هذه المفاتيح ذات صلاحيات واسعة، لذا تبقى في الخادم ولا تُرسل لتلجرام.
4. سجّل webhook عبر `setWebhook` في Telegram Bot API من أداة خادمية آمنة:
   - `url`: `https://rglbfizqolrenwfsndyv.supabase.co/functions/v1/telegram-admin`
   - `secret_token`: نفس قيمة `TELEGRAM_WEBHOOK_SECRET`.
   - `allowed_updates`: `["message", "callback_query"]`.
   لا تعرض مفتاح البوت في سجل الأوامر أو المخرجات، ولا تستبدل webhook لبوت
   موجود يخدم غرضاً آخر. لا تستخدم `drop_pending_updates` في هذا الإعداد.
5. افتح البوت من حساب المالك واضغط Start ثم «فحص الربط بالمتجر».

## معايير نجاح الاختبار الفعلي

- تصل نتيجة نجاح اتصال قاعدة البيانات إلى حساب المالك في الخاص.
- حساب آخر لا يتلقى بيانات أو ينفذ فحصاً.
- مجموعة أو callback من مستخدم آخر لا ينفذ فحصاً.
- لا تتغير الطلبات أو الأرصدة نتيجة الاختبار.

## التشغيل والتحقق

```sh
npm run test:telegram
npm run test:telegram-db
deno check supabase/functions/telegram-admin/index.ts
```

`verify_jwt = false` خاص بهذه الدالة لأن Telegram لا يرسل JWT تابعاً
لـSupabase. التعويض داخل الدالة إلزامي: سر webhook ومعرف المالك وربط
المحادثة الخاصة. غياب الإعداد يمنع العمل. لا تُطبع تحديثات تلجرام أو
أجسام أخطاء الخدمات أو روابط API التي تتضمن مفتاح البوت.

## المرحلة التالية بعد نجاح الربط

تحديد مجموعة إدارية خاصة، وربط الإداري بهوية الموقع وصلاحياته، ثم بناء
تنبيهات الطلبات وأزرار العرض والانتقالات الآمنة للحالة. يجب أن تعيد الأزرار
استخدام ضوابط الدفع الحالية في `admin_update_order_status`، مع سجل تدقيق
ومنع التكرار وسباق التنفيذ. لا يكفي تعديل `orders.status` مباشرة.
