# تصميم تحسين الأمان والاستقرار والواجهة

**التاريخ:** 2026-07-29
**النطاق:** متجر RAIZEY STORE متعدد الصفحات مع تكامل Supabase من الواجهة

## الهدف

تنفيذ إصلاحات محافظة تعالج مشاكل الأمان في الواجهة، وتوحد إعداد Supabase، وتزيل أي نصوص JavaScript أو HTML غير آمنة، وتحسن الواجهة والاستجابة، مع الحفاظ التام على السلوك الحالي للمتجر ولوحة الإدارة.

## المشاكل المؤكدة

- وجود حقن مباشر لبيانات قاعدة البيانات داخل `innerHTML` في صفحات إدارة متعددة، ما يفتح باب XSS أو كسر HTML.
- وجود نسختين من ملف Supabase client في `supabase-client.js` و`assets/js/supabase-client.js` مع إعدادات مكررة.
- اعتماد واسع على الاستعلامات المباشرة من المتصفح، ما يجعل قوة الحماية مرتبطة مباشرة بسياسات RLS وRPC.
- وجود بعض الرسائل المعتمدة على Emojis في الواجهة بدل مؤشرات بصرية متسقة مع التصميم.
- وجود بعض الروابط والخصائص الديناميكية التي تحتاج تهريبًا أو تقييدًا إضافيًا.

## التصميم المعتمد

### 1. طبقة حماية مشتركة في الواجهة

سيتم توسيع `assets/js/supabase-client.js` ليصبح ملف المرافق الأمني المشترك، مع إضافة دوال عامة للتهريب والتحقق مثل:

- `escapeHtml()`
- `escapeAttribute()`
- `safeDataAttr()`
- `sanitizeUrl()`
- `safeText()`

هذه الدوال ستستخدم في القوالب التي تبني HTML ديناميكياً، مع إبقاء السلوك الحالي والـ DOM structure كما هو قدر الإمكان.

### 2. توحيد إعداد Supabase

- اعتماد `assets/js/supabase-client.js` كمصدر وحيد.
- تحويل ملف الجذر `supabase-client.js` إلى طبقة توافق بسيطة أو توجيه واضح لتجنب الانحراف بين النسختين.
- دعم تحميل الإعداد من `window.__SUPABASE_CONFIG__` إن وُجد، مع fallback للإعداد الحالي حتى لا ينكسر التشغيل الحالي.

### 3. إصلاح الصفحات عالية الخطورة

الأولوية ستكون لصفحات الإدارة والصفحات التي تعرض بيانات مستخدمين أو سجلات:

- `admin-audit-log.html`
- `admin-topups.html`
- `admin-categories.html`
- `admin-customers.html`
- `admin-coupons.html`
- `admin-giftcards.html`
- `admin-payment-methods.html`
- `admin-referral-milestones.html`
- `admin-products.html`
- `admin-orders.html`

سيتم تهريب كل النصوص والخصائص والروابط الديناميكية داخل هذه الصفحات مع الحفاظ على نفس واجهات التحكم.

### 4. تحسين الواجهة

- إزالة الـ Emojis المستخدمة في الرسائل واستبدالها بنصوص نظيفة أو أيقونات Font Awesome الموجودة أصلاً في المشروع.
- تحسين بعض عناصر لوحة الإدارة وصفحات المنتج لتظهر بشكل عصري ومتسق.
- مراجعة CSS المرتبط بالتجاوب، خاصة في القوائم والبطاقات والأزرار داخل الشاشات الصغيرة.

### 5. مراجعة SQL والسياسات

- مراجعة `supabase-security.sql` لسد الفجوات التوثيقية والعملية المتعلقة بالجداول المستخدمة من الواجهة.
- إضافة ملاحظات أو سياسات مساعدة فقط عند الحاجة وبدون تغيير سلوك الجداول الحالية بشكل قد يكسر التشغيل.

## قيود التنفيذ

- لا إعادة بناء معمارية كبيرة.
- لا نقل كامل لمنطق الواجهة إلى framework جديد.
- لا تغيير لسلوك الشراء، الدفع، الإدارة، أو تدفقات الحساب.
- كل تعديل يجب أن يكون محافظًا وذا أثر موضعي واضح.

## التحقق

- فحص تشخيصي للملفات المعدلة بعد كل دفعة.
- تشغيل بناء المشروع والتحقق من عدم وجود أخطاء صياغية واضحة.
- إنشاء أرشيف `modified_files.zip` يحتوي فقط على الملفات التي تم تعديلها أو إنشاؤها.
